# <span style="color:#5CFF7A">x402 fwog · 第一代两栖链上人工智能</span>

> <span style="color:#7BFF4A">“如果 fwog 不只是个梗呢。如果它真正接入了网络呢。”</span>  

x402 fwog 是一个围绕 BNB Chain 构建的实验性两栖人工智能系统。  
这里的“两栖”有三层含义：

1. 在链上和链下之间自由切换  
2. 在模因文化和严肃基础设施之间自由切换  
3. 在人类指令和自主演化行为之间自由切换  

本仓库并不是一个单一合约或单一模型的代码集合，而是一个完整的研究型实现：  
从协议设计、智能体架构、数据流拓扑，到仿真环境与安全假设，全部开源并可复现。

---

## <span style="color:#66FF66">1. 命名与背景</span>

### 1.1 为什么是 x402

x402 来源于两个维度：

- “402” 在 BNB 社区中被视为高风险高回报的象征  
- x 前缀代表实验性、可扩展和向量化  
- 在内部文档中，x402 被定义为 “一组自适应流动性与注意力分配算法的编号”

### 1.2 为什么是 fwog

fwog 是一个来自 BNB 生态的青蛙模因。  
在 x402 体系中，fwog 不再只是头像或图片，而是被赋予了下列角色：

- 网络边缘的观察者  
- 链上事件的压缩叙事者  
- 风险情绪与资金流之间的“翻译器”  

我们将这种重新定义称为 **“模因提升”**。

## <span style="color:#6EFF8A">2. 整体架构总览</span>

从宏观上看，x402 fwog 由四个层级组成：

1. 感知层 Perception Layer  
2. 决策层 Decision Layer  
3. 执行层 Execution Layer  
4. 叙事层 Narrative Layer  

它们共同形成一个闭环：

> 区块数据 → 特征图 → 行为建议 → 实际执行 → 事件压缩 → 回写记忆

### 2.1 感知层

感知层的核心任务是“听得见链上的细语”。  
主要组成部分：

- 区块监听与事件过滤器  
- 价格与深度聚合器  
- BNB 生态特有事件适配器  
  - 新合约创建  
  - 流动性注入与抽离  
  - 大额转账与分布聚类  

感知层输出的不是单一数值，而是一组高维稀疏张量，交由决策层消费。

### 2.2 决策层

决策层由三种不同风格的模型并行工作：

- 统计贝叶斯型模型  
- 序列决策型模型  
- 模因情绪编码模型  

它们按照“投票权重”合成一个统一的 Action Proposal，对 Execution Layer 发起请求。

### 2.3 执行层

执行层的职责非常单纯：可靠而透明地执行决策。

- 所有链上操作在进入执行层前会被再度审计  
- 执行层只能通过事先白名单化的 Router 合约完成交互  
- 任何高风险操作都会触发多级冷却与人工确认通道  

执行层的所有行为都会写入可验证的执行日志，为之后的回放与仿真提供数据。

### 2.4 叙事层

叙事层是 x402 fwog 与人类沟通的接口。  
它会将复杂的链上行为压缩为可读的文本片段、时间线与图形描述。  

在设计上，叙事层遵循三个原则：

1. 不夸大收益  
2. 不隐藏风险  
3. 不制造虚假确定性  

---

## <span style="color:#71FF9C">3. “两栖 AI” 的含义</span>

传统的链上机器人往往是单向的：只对价格做出反应。  
x402 fwog 的“两栖”特性则表现在三方面：

1. 链上与链下并行  
   - 链下模型对大规模历史数据进行训练  
   - 链上逻辑控制权限、阈值和风险  
2. 数据与模因并行  
   - 纯数值信号和社区叙事同时纳入决策  
3. 自动化与人工干预并行  
   - 维护者随时可以在“完全自动”和“只读观察”之间切换  

这一设计的目标，是让 x402 在极端市场条件下仍然保持可解释、可关停与可恢复。

## <span style="color:#73FFA8">4. BNB Chain 集成设计</span>

x402 fwog 从一开始就针对 BNB Chain 进行了深度定制。

### 4.1 链上组件

仓库中的链上部分示例合约包括：

- `FwogGuardian.sol`  
  - 访问控制与角色管理  
  - 审计所有关键函数调用  
- `LiquiditySentinel.sol`  
  - 监控 LP 变动  
  - 自动触发风控逻辑  
- `MemeOracle.sol`  
  - 将外部情绪指数写入链上  
  - 对 AI 决策的某些分支起限幅作用  

这些合约并非用于生产，而是作为研究用途的参考实现。

### 4.2 Gas 与性能假设

x402 在设计时遵循以下原则：

- 合约本身保持“愚蠢”，只负责约束与记录  
- 复杂计算尽量在链下执行  
- 所有可选功能按模块拆分，避免巨石合约  

通过这种方式，可以在测试环境中快速迭代，而不牺牲主网的安全性。

## <span style="color:#76FFB4">5. x402 协议层细节</span>

x402 协议层提出了一个简单但极具表达力的抽象：  

> 每一次链上交互都可以分解为  
> 状态视图、风险预算、意图描述、执行约束 四个部分。

在代码中，这被建模为一个结构体：

```text
struct Intent {
    StateView state;
    RiskBudget budget;
    NarrativeTag[] tags;
    Constraint[] constraints;
}
```

所有 AI 生成的行为，最终都会降解成一个或多个 Intent 实例。  
执行层只接受满足白名单约束的 Intent。

## <span style="color:#7AFFBF">6. 关键模块说明</span>

本仓库按功能分成若干模块，每个模块都有独立的设计文档。

- `src/amphibious_core.py`  
  - 两栖智能体的主循环  
  - 负责在不同“水位”之间切换风险模式  
- `src/meme_adapter.py`  
  - 接收来自社区、推文或论坛的文本流  
  - 将其转化为定量情绪特征  
- `src/liquidity_observer.py`  
  - 监听特定池子的深度变化  
  - 对突然抽干给出预警评分  
- `src/policy_sandbox.py`  
  - 对不同风控策略进行离线回测  
  - 可定义历史窗口、目标指标和边界条件  

所有模块都围绕一个核心思想：  
**在任何时刻，x402 都应能解释“自己为什么这样做”。**

## <span style="color:#7DFFCA">7. 本地运行与实验</span>

本仓库主要面向研究者和高级用户。  
普通用户不需要在本地运行任何组件即可理解整体理念。  

### 7.1 环境要求

- Python 3.11 或更高  
- 一个只读或小额资金的 BNB 钱包  
- 可访问公共 BNB 节点或自建节点  

### 7.2 安装步骤

```bash
git clone https://github.com/your-account/x402-fwog.git
cd x402-fwog

python -m venv venv
source venv/bin/activate  # Windows 用户请使用 venv\Scripts\activate

pip install -r requirements.txt
```

### 7.3 启动观测模式

观测模式下，x402 不会执行任何链上事务，只会打印决策建议。

```bash
python src/amphibious_core.py --mode observe
```

你将看到如下信息流：

- 当前监控的池子与合约  
- 对应的风险评分  
- 生成但未执行的 Intent 列表

## <span style="color:#80FFD4">8. 安全模型与边界</span>

x402 fwog 是一个研究项目，而非立即可投入生产的资产管理工具。  

在安全设计上，我们坚持以下边界：

1. 永远假定模型会犯错  
2. 永远假定节点可能被中断  
3. 永远假定网络可能被分叉  

因此，所有示例策略都遵循“先求活下来，再谈表现”的思路：

- 默认使用极小仓位  
- 所有操作有时间与频率上限  
- 任何异常信号都会自动切换到只读模式  

如果你决定在真实资金环境下实验，请自行进行完整审计与压力测试。

## <span style="color:#89FFF4">12. 常见问题</span>

### 问题 1：x402 fwog 是否会自动帮我赚钱

不会。  
本项目的目标是探索“模因驱动的两栖 AI 架构”，而不是提供保证收益的系统。  
任何与资金相关的实验都应在你完全理解风险后再进行。

### 问题 2：为什么仓库里很多模块看起来是“半完成”

因为我们选择把真实的研究过程公开出来，而不是只展示已经打磨好的结果。  
这意味着你会看到：

- 被废弃的思路  
- 仍在验证阶段的算法  
- 不同版本之间的明显矛盾  

这正是研究型仓库应有的样子。

### 问题 3：我可以在其他链上重建 x402 吗

可以。  
理论上，只要目标链支持足够丰富的事件订阅与可靠的节点连接，就可以迁移 x402 的大部分思路。  
我们在 `docs/porting.md` 中给出了一份迁移清单，包含需要注意的所有环节。
